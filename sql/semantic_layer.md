# Semantic layer — inject this into the SQL-generation prompt

Generated by `scripts/build_semantic_layer.py` from the live views in
`sql/views.sql`. Do not edit by hand; edit the script and re-run.

These views already handle every known trap in the raw data. Query them
directly. Never read the raw CSVs, and never use a column that is not
listed here.

## Rules

1. Every view already has a `neighborhood` column EXCEPT property, property_homes and open_space. Never write a spatial join yourself.
2. property and property_homes have NO coordinates. They join to other tables by `zipcode` only.
3. open_space has no coordinates and no neighborhood. It joins by `zipcode` only.
4. 311 data covers 2026 only (Jan-Aug). Any question comparing 311 to a previous year is UNANSWERABLE - say so, do not write SQL.
5. Crime 2026 is partial (Jan 15 Aug). Never compare a full year to 2026 without restricting to `month <= 8`.
6. Use `crime_only` for crime questions. `crime` includes non-crimes and will overstate by ~97%.
7. Use `food_inspections` for inspection counts and rates. `food_violations` has ~4x more rows.
8. Use `property_homes` for typical home value. `property` includes 8,545 parking spaces worth ~$44,000 each.
9. 311 `hours_to_close` is NULL for the 49.1% of cases still open. Report the open-case count alongside any median.
10. Licence tables contain only active records. Questions about revoked or expired licences are UNANSWERABLE.
11. `on_time` in svc311 is pre-computed by the city ('ONTIME' / 'OVERDUE'). Use it, do not recompute from timestamps.

## Example questions and correct SQL

**How many crimes were there in Roxbury in 2025?**

```sql
SELECT count(*) FROM crime_only WHERE neighborhood = 'Roxbury' AND year = 2025;
```

**Which neighborhood has the most violent crime?**

```sql
SELECT neighborhood, count(*) AS n FROM crime_only
WHERE crime_class = 'violent' AND neighborhood IS NOT NULL
GROUP BY 1 ORDER BY n DESC LIMIT 1;
```

**Is crime in Dorchester getting better or worse?**

```sql
-- 2026 is Jan-Aug only, so compare like-for-like windows.
SELECT year, count(*) AS n FROM crime_only
WHERE neighborhood = 'Dorchester' AND month <= 8
GROUP BY 1 ORDER BY 1;
```

**Which neighborhood waits longest for 311 requests?**

```sql
SELECT neighborhood,
       median(hours_to_close) AS median_hours,
       count(*) FILTER (WHERE is_open) AS still_open
FROM svc311 WHERE neighborhood IS NOT NULL
GROUP BY 1 ORDER BY median_hours DESC;
```

**What do people in East Boston complain about most?**

```sql
SELECT type, count(*) AS n FROM svc311
WHERE neighborhood = 'East Boston' GROUP BY 1 ORDER BY n DESC LIMIT 10;
```

**What is the median home value in each neighborhood?**

```sql
-- property has no coordinates; it joins by zipcode.
SELECT p.zipcode, median(p.total_value) AS median_value, count(*) AS n
FROM property_homes p GROUP BY 1 ORDER BY median_value DESC;
```

**What is the most valuable property in Boston?**

```sql
SELECT owner, street_address, total_value
FROM property ORDER BY total_value DESC LIMIT 5;
```

**What share of restaurant inspections fail?**

```sql
SELECT result, count(*) AS n,
       round(100.0 * count(*) / sum(count(*)) OVER (), 1) AS pct
FROM food_inspections GROUP BY 1 ORDER BY n DESC;
```

**How many 311 cases were closed on time in Mattapan?**

```sql
SELECT on_time, count(*) FROM svc311
WHERE neighborhood = 'Mattapan' GROUP BY 1;
```
